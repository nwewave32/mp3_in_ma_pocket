## 🎯 요청 / 배경

프리뷰 앱은 샘플 곡만 넣어 보여줬다. 사용자가 가진 mp3를 실제로 앱 폴더에 가져오는 MVP 첫 요구사항(F1)과, 같은 이름 파일 처리(F3)가 필요했다.

## 🔧 한 일

- `lib/library/mp3_library.dart` 새로 작성
  - `Mp3Library`: 앱 Documents 폴더에서 mp3 읽기와 가져오기 담당. 폴더 위치와 파일 선택기를 바꿔 끼울 수 있다(`Mp3Picker` typedef).
  - `importFromPicker()`: `file_picker`로 mp3만 여러 개 고르게 하고, 취소하면 `null`을 돌려준다. 끝나면 `_clearPickerCopies()`로 선택기 임시 사본을 지운다.
  - `copyIn()`: 파일 이름을 `basename()`으로 정리하고 mp3가 아니면 건너뛴다. `'$target.part'`로 복사한 뒤 이름을 바꿔서, 복사에 실패한 파일이 곡으로 나타나지 않게 했다.
  - `_freePath()`: 이름이 겹치면 `"Song 2.mp3"`, `"Song 3.mp3"`처럼 번호를 붙인다(F3).
  - `list()`: 최상위 폴더의 mp3만 읽는다(`followLinks: false`).
  - `ImportResult { imported, failed }`
- `lib/design/design_preview.dart`
  - 시작할 때 Documents에서 목록을 읽는다(`_reload()`).
  - `_import()`: 실패하면 "Couldn't import N files." 같은 스낵바를 띄운다.
  - `PreviewPlayer.setTracks()`: 목록이 바뀌어도 재생 중인 곡을 유지한다.
- `lib/design/screens/library_screen.dart`: `SoftTrack.duration`을 `Duration?`로 바꾸고, 길이를 모르면 `--:--`를 표시한다.
- `ios/Runner.xcodeproj/project.pbxproj`: `IPHONEOS_DEPLOYMENT_TARGET`을 14.0으로 올렸다(프로젝트 3곳, Runner 타깃 3곳).
- `pubspec.yaml`: `file_picker`, `path_provider`, `path` 추가
- 테스트
  - `test/mp3_library_test.dart` 새로 작성: 여러 개 복사, mp3 아닌 파일 건너뛰기, 취소, 원본이 없을 때 남는 파일 없음, F3 번호 붙이기(기존 파일과 겹칠 때, 한 번에 고른 파일끼리 겹칠 때)
  - `test/design_screens_test.dart`: 첫 실행 → 가져오기 → 목록 흐름

## 🧩 이슈 · 해결

- iOS 빌드 실패: "file-picker-darwin requires minimum platform version 14.0 … target supports 13.0"
  - 원인: 프로젝트 설정만 14.0으로 바꾸면, Runner 타깃 설정이 없어서 SPM 매니페스트가 13.0으로 다시 만들어졌다.
  - 해결: Runner 타깃 3곳에도 `IPHONEOS_DEPLOYMENT_TARGET = 14.0`을 추가했다.
- 실제 파일 입출력을 쓰는 위젯 테스트에서 화면이 갱신되지 않았다. `tester.runAsync`와 `pump`를 반복하는 방식으로 해결했다.
